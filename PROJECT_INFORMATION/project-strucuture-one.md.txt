# EnPay E-Wallet System - Project Framework & Architecture Analysis

## 1. Project Overview

**Project Name:** EnPay E-Wallet System  
**Group ID:** `com.enpay`  
**Artifact ID:** `enpay`  
**Version:** `0.0.1-SNAPSHOT`  
**Packaging:** Multi-module Maven POM  
**Description:** Secure Distributed Microservice-Based E-Wallet System  

EnPay is a microservice-based digital wallet platform built with Spring Boot 3.4.5 and Spring Cloud 2024.0.1. It supports multi-currency wallets, collaborative expense collections with advanced bill-splitting algorithms, settlement and netting transactions, exchange rate management, notifications, and reporting dashboards.

---

## 2. Technology Stack

### 2.1 Core Framework
| Component | Technology | Version |
|---|---|---|
| Language | Java | 17 |
| Framework | Spring Boot | 3.4.5 |
| Cloud Framework | Spring Cloud | 2024.0.1 |
| Build Tool | Apache Maven | Wrapper included (mvnw) |
| JDK Runtime | Eclipse Temurin | 17-jre-alpine (Docker) |

### 2.2 Spring Cloud Components
| Component | Purpose |
|---|---|
| Spring Cloud Config Server | Centralized configuration management (native file-based) |
| Netflix Eureka Server/Client | Service discovery and registry |
| Spring Cloud Gateway | API gateway with reactive routing |
| Spring Cloud OpenFeign | Declarative REST client for inter-service communication |
| Resilience4j (Circuit Breaker, Retry, Time Limiter) | Fault tolerance and resilience patterns |

### 2.3 Data & Messaging
| Component | Technology | Version |
|---|---|---|
| Relational Database | MySQL | 8.0 |
| Caching | Redis | 7 (Alpine) |
| Message Broker | RabbitMQ | 3 (Management Alpine) |
| ORM | Hibernate / Spring Data JPA | (via Spring Boot) |

### 2.4 Security
| Component | Technology |
|---|---|
| Authentication | JWT (JSON Web Token) via `jjwt` library v0.12.6 |
| Password Hashing | BCrypt (via Spring Security) |
| Gateway Auth Filter | Custom `JwtAuthenticationFilter` in API Gateway |
| Framework | Spring Security (stateless, CSRF disabled) |

### 2.5 Libraries & Utilities
| Library | Purpose |
|---|---|
| Lombok | Boilerplate reduction (@Builder, @Data, @Getter, @Setter, etc.) |
| Jackson | JSON serialization/deserialization |
| Jakarta Validation | Request DTO validation (@NotBlank, @Email, @Size, etc.) |
| Spring AOP | Aspect-oriented role-based authorization in collection-service |

### 2.6 Containerization & Deployment
| Component | Technology |
|---|---|
| Containerization | Docker (per-service Dockerfile) |
| Orchestration | Docker Compose (v3.8) |
| Base Image | `eclipse-temurin:17-jre-alpine` |

### 4.3 Service Startup Order

```
1. mysql, redis, rabbitmq            (Infrastructure - parallel)
2. config-server                      (Must be healthy before any Spring service)
3. discovery-server                   (Must be healthy for service registration)
4. api-gateway                        (Needs discovery-server + redis)
5. auth-service                       (Needs discovery-server + mysql)
6. wallet-service                     (Needs discovery-server + mysql)
7. collection-service                 (Needs discovery-server + mysql + rabbitmq)
8. transaction-service                (Needs discovery-server + mysql + rabbitmq)
9. currency-service                   (Needs discovery-server + mysql + redis)
10. notification-service              (Needs discovery-server + mysql + rabbitmq)
11. reporting-service                 (Needs discovery-server only)
```

### 4.4 Configuration Management Strategy

The project uses a **two-tier configuration** strategy:

1. **Local `application.yml`** (per service): Contains baseline configuration for local development (localhost references)
2. **Config Server `configurations/`**: Contains the same configuration plus additional settings (CORS, Resilience4j, etc.) — fetched at runtime via `spring.config.import: optional:configserver:http://localhost:8888`
3. **Docker profile overrides** (`*-docker.yml`): Replaces `localhost` with Docker service names (e.g., `mysql`, `redis`, `rabbitmq`, `discovery-server`)

The `optional:` prefix allows services to start standalone without the config server for local development.

## 6. API Route Summary (Gateway Routes)

All client requests enter through the API Gateway on port **8080**:

| Route Pattern | Target Service | Service ID |
|---|---|---|
| `/api/auth/**` | auth-service | AUTH-SERVICE |
| `/api/wallets/**` | wallet-service | WALLET-SERVICE |
| `/api/collections/**` | collection-service | COLLECTION-SERVICE |
| `/api/transactions/**` | transaction-service | TRANSACTION-SERVICE |
| `/api/currency/**` | currency-service | CURRENCY-SERVICE |
| `/api/notifications/**` | notification-service | NOTIFICATION-SERVICE |
| `/api/reports/**` | reporting-service | REPORTING-SERVICE |

**Open paths (no JWT required):** `/api/auth/register`, `/api/auth/login`, `/api/auth/refresh`

All other paths require a valid JWT `Bearer` token in the `Authorization` header. The gateway extracts the `userId` from the token and forwards it as the `X-User-Id` header to downstream services.

## 7. Cross-Cutting Concerns

### 7.1 Exception Handling
- `GlobalExceptionHandler` in `common-lib` provides base handling for all exceptions
- Each service extends it with a local `*ExceptionHandler` class
- Standardized `ApiResponse<T>` envelope for all responses

### 7.2 Money Handling
- All monetary amounts use `BigDecimal` with scale=4 and `HALF_UP` rounding
- `MoneyUtil` utility class provides safe arithmetic operations
- `RemainderDistributor` handles penny-level precision in bill splitting

### 7.3 Resilience Patterns
- **Circuit Breaker:** Resilience4j with configurable sliding windows and failure thresholds
- **Retry:** Exponential backoff with max 3 attempts for IO/timeout exceptions
- **Time Limiter:** 3-5 second timeouts on inter-service calls
- **Fallback Factories:** Every Feign client has a `FallbackFactory` for graceful degradation

### 7.4 Messaging Architecture
- **Exchange:** `enpay.notifications` (Topic Exchange)
- **Queues:** `enpay.notifications.settlement`, `enpay.notifications.expense`, `enpay.notifications.invitation`
- **Routing Keys:** `notification.settlement.#`, `notification.expense.#`, `notification.invitation.#`
- **Producers:** transaction-service, collection-service
- **Consumer:** notification-service (3 listeners)

### 7.5 Rate Limiting
- Redis-based rate limiting on transaction routes via Spring Cloud Gateway
- Rate: 5 requests/second, burst capacity: 10
- Key resolver: `X-User-Id` header or client IP fallback
