overall specification
the project must follow the below principle unless no choice
- low coupling
- SOLID principle (single responsibility principle, open closed principle, interface segregation principle, dependency inversion principle)
- tell Don't ask
- once and only once
- the law of demeter
- package principle
- don't repeat yourself (DRY)
- you ain't gonna need it (YAGNI)

principle of microservice system
- single Responsibility
- decentralized data management
- API-driven communication
- high fault tolerance
- automated DevOps processes to enhance developer agility

entity name: all UPPERCASE, singular
table name: all uppercase with _T at the end (ex: EMPLOYEE_T)
attribute name in the table: all lowercase, start with the first 3/4 letters of the table name or the initial of the name of the table (ex: memb_name from MEMBER_T, bs_name from BOOK_SUPPLIER_T), some attribute can be split into smaller attributes
method name: lower camel case
class name: upper camel case

database
- ID must be char or integer
- length fixed: char, not fixed: varchar

must have
- exception handler
- close file after using
- null handler
